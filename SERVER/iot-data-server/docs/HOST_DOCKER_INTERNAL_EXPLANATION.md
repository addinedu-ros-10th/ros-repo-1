# `host.docker.internal` 설명

## 📖 `host.docker.internal`이란?

`host.docker.internal`은 **Docker 컨테이너에서 호스트 머신(컨테이너를 실행하는 머신)에 접근하기 위한 특별한 호스트명**입니다.

### 의미

- **"host"**: Docker를 실행하는 호스트 머신 (컨테이너가 아닌 실제 물리적/가상 머신)
- **"docker.internal"**: Docker가 내부적으로 제공하는 특별한 DNS 이름

### 동작 방식

```
┌─────────────────────────────────────┐
│  호스트 머신 (예: 192.168.0.10)      │
│  ┌───────────────────────────────┐  │
│  │  Docker 컨테이너              │  │
│  │  ┌─────────────────────────┐  │  │
│  │  │  iot-care-app           │  │  │
│  │  │                         │  │  │
│  │  │  DB_HOST=               │  │  │
│  │  │  host.docker.internal   │  │  │
│  │  │         ↓                │  │  │
│  │  │  호스트 머신으로 연결     │  │  │
│  │  └─────────────────────────┘  │  │
│  └───────────────────────────────┘  │
│           ↑                          │
│           │                          │
│  ┌────────┴────────┐                │
│  │ PostgreSQL      │                │
│  │ (포트 15432)     │                │
│  └─────────────────┘                │
└─────────────────────────────────────┘
```

### 답변

**Q: docker를 운용하는 머신의 IP를 사용한다는 거야?**
- ✅ **네, 맞습니다!** `host.docker.internal`은 Docker를 실행하는 호스트 머신(컨테이너를 실행하는 머신)의 IP를 자동으로 가리킵니다.

**Q: 아니면 컨테이너의 IP를 사용한다는 거야?**
- ❌ 아닙니다. 컨테이너의 IP가 아니라 **호스트 머신의 IP**를 사용합니다.

### 예시

**시나리오:**
- 호스트 머신 IP: `192.168.0.10`
- Docker 컨테이너 내부에서 `host.docker.internal` 사용
- 결과: `192.168.0.10`으로 연결 시도

**장점:**
- 호스트 IP가 변경되어도 코드 수정 불필요
- Docker가 자동으로 호스트 IP를 해석

**단점:**
- Linux에서는 기본적으로 지원되지 않음 (Docker Desktop에서는 지원)
- `docker-compose.yml`에 `extra_hosts` 설정 필요

### 현재 프로젝트 상황

**docker-compose.yml**에 이미 설정되어 있음:
```yaml
extra_hosts:
  - "host.docker.internal:host-gateway"
```

이 설정으로 Linux에서도 `host.docker.internal` 사용 가능합니다.

## 🔄 사용자 요구사항 반영

사용자는 다음을 요청했습니다:

1. **항상 env 파일의 환경 변수 값을 사용**
   - `.env.local`의 `DB_HOST` 값을 그대로 사용
   - 임의로 변경하지 않음

2. **연결 실패 시 명확한 로그 메시지**
   - "env 파일의 HOST로 DB 연결이 불가능하니 env 파일을 확인해달라"는 메시지

3. **임의로 연결 값을 설정하지 않음**
   - `host.docker.internal`로 자동 변경하지 않음
   - 사용자가 설정한 값 그대로 사용
